# 小爱同学控制：米家中枢网关「虚拟事件」方案（已打通 ✅）

> 实测通过：**米家 App / 小爱 → 中枢网关虚拟事件 → HA 自动化 → 按摩椅**，
> 不需要巴法云、不需要第三方云、不需要额外硬件。

```
小爱同学 ──▶ 米家手动场景 ──▶ 中枢网关·产生虚拟事件（内容=指令名）
                                      │
                         xiaomi_home 集成（本地链路）
                                      ▼
                              HA 自动化（读 事件名称）
                                      ▼
                            按摩椅（rtchair 集成）
```

## 一、实测结果（2026-10-28）

| 环节 | 结果 |
|---|---|
| 米家中枢网关 → HA 虚拟事件 | ✅ 收到，事件属性 `事件名称` = 虚拟事件内容 |
| HA 自动化 → 按摩椅 | ✅ 椅子收到开机指令、响开机音、进入待机 |
| 米家集成云端 mips 报错 | 有报错但**不影响**虚拟事件（走本地链路） |
| 极客版验证码 | 一次性，登录后失效 |

## 三、米家 / 小爱侧配置

### 3.1 建米家手动场景（每个指令一个）

米家 App → 智能 → **手动场景** → 新建：

1. 添加动作 → 选择 **中枢网关** 设备
2. 选择动作 **产生虚拟事件**，内容填：`按摩椅开机`
3. 保存，命名为「按摩椅-开机」

> 对每个指令重复一遍，内容严格按上面的对照表填（中文、不要多空格）。

### 3.2 小爱训练绑定语音

小米音箱 App / 小爱同学 App → **训练** → 添加：

- 对她说：`打开按摩椅`
- 执行动作：**执行场景** → 「按摩椅-开机」

> 也可以直接说「小爱同学，执行按摩椅-开机」。

### 3.3 推荐先建这 3 条

`打开按摩椅`（开机）、`关闭按摩椅`（关机）、`打开肩颈重点`（预设程序）。

## 四、排障

| 现象 | 排查 |
|---|---|
| 说了没反应 | 看 HA 日志有没有 `RTVE ... 事件名称`；没有 → 米家场景没产生事件 |
| 收到事件但椅子不动 | 事件名称和对照表不一致（大小写/空格/简繁） |
| 椅子没反应但日志有 | 检查 rtchair 集成是否可用、broker 是否在线 |
| 米家集成 mips 报错 | 不影响虚拟事件，可忽略 |

日志位置：`/config/home-assistant.log`，搜 `RTVE`。

## 五、为什么不用别的方案

| 方案 | 结论 |
|---|---|
| 巴法云 | 要第三方云账号，用户不希望 |
| 极客版规则 | 只能操作米家设备，没有 HTTP/网络动作，无法直连 HA |
| 信号设备桥 | 需要占用一个米家设备当"暗号"，虚拟事件方案更干净 |
| MQTT/直连 MCU | 已实测不可行（见固件评估文档） |
