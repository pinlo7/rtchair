# 固件与刷机评估（RT7709S）

> 结论先说：**不建议刷机**。刷固件既补不出「摇椅」（缺机械机构），也很可能把椅子刷成砖。
> 本文记录的是我们实际查到的固件版本、升级通道和只读侦察方法。

---

## 1. 当前固件版本（云端 `QueryDevicePropertyStatus` 实测）

| 字段 | 版本 |
|---|---|
| ControllerVersion（主控） | **18.28** |
| MainVersion（主程序） | **1.15** |
| UserInterfaceVersion（界面） | **5.19** |
| ControllerConfigVersion | **0.00** |
| 模组型号 | 汉枫 HF-LPB130（Wi-Fi 转串口） |

## 2. 升级通道（逆向 App + 抓包确认）

### 2.1 云端 MQTT（模组侧，真正的刷机通道）

椅子连接阿里云 IoT 后订阅了：

```
/sys/<PRODUCT_KEY>/<DEVICE_NAME>/thing/service/ServiceUpgrade
/sys/<PRODUCT_KEY>/oQXHWJeL49SGoIvNRmK2/thing/service/ServiceUpTriad
/sys/<PRODUCT_KEY>/oQXHWJeL49SGoIvNRmK2/thing/service/ServiceMagic
/sys/<PRODUCT_KEY>/oQXHWJeL49SGoIvNRmK2/rrpc/request/+
```

其中 `ServiceUpgrade` 就是官方推送固件升级的入口（含下载 URL / 版本 / md5 等）。
我们在离线模式下**冒充阿里云**，所以理论上能"收到"官方升级推送——但前提是官方主动推，
而且固件包有签名/MD5 校验，自己造包发过去会被拒。

### 2.2 App 侧 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/bodydata/v1/device/status?mac=` | 设备在线状态（只读，可安全调用） |
| GET | `/api/bodydata/v1/firmware/upgradeProgress?mac=` | 升级进度（只读，可安全调用） |
| POST | `/api/bodydata/v1/firmware/upgrade` | **危险**：给椅子下发真实升级指令 |
| POST | `/api/bodydata/v1/device/primary/bind` | 绑定设备 |
| POST | `/api/bodydata/v1/iot` | 属性读写（我们离线方案同源） |

POST `firmware/upgrade` 的请求体（反编译 `NetUpgradeRunnable`）：

```json
{"url": "<固件包 OSS 地址>", "version": "<目标版本>",
 "mac": "AABBCCDDEEFF", "nwm_model": "<模组型号>",
 "md5": "<固件 md5>", "size": <字节数>}
```

也就是说：**App 本身不提供"查最新版本"，它拿到 update 信息后直接 POST 让椅子升级**。

### 2.3 只读侦察实测结果

```bash
python3 tools/ota_watch.py --cloud
# device/status   -> {"code":0,"message":"ok","data":{"status":"offline"}}
#                 （离线模式下椅子不在云上，这是正常的）
# upgradeProgress -> {"code":0,"message":"ok","data":{"progress":0}}
```

结论：**没有安全的"查最新固件"接口**——要查只能让椅子回云端，而回云端后 App 的"检查升级"
一旦点到就会真下发。官方是否发布过新固件，我们无法在不冒险的情况下确认。

## 3. 为什么刷机解决不了摇椅问题

1. **机械缺失**：RT7709S 没有摇椅机构（RT7709Pro / A50Max 等才有）。固件里就算有
   `RockingChairSwitch` 的处理代码，也没有执行机构，最多空转。
2. **电机恒速**：靠背/腿托/零重力都是固定电压驱动，速度写在固件里；改速度要重写
   PWM 控制逻辑，需要完整固件逆向 + 重烧，不是改个参数。
3. **直连 MCU 发原始命令也无效**（本次实测）：
   - 向 8899 发 `0x2441`（零重力）/`0x2451`（摇椅），MCU 都回 ACK；
   - 但发**不存在的命令 `0x2999` 也回 ACK** → ACK 只是"帧格式合法"的通用应答；
   - 发 `0x0001`（开机）椅子毫无反应 → MCU 不执行外部裸帧，真正的命令翻译在模组固件里。
4. **刷机风险**：MCU 固件有签名校验、无公开包、无调试口（要拆机 + SWD + 编程器）；
   刷坏 = 变砖，保修作废，无法软恢复。

## 4. 如果真要研究（风险自担）

准备清单：

- [ ] 备用控制板（或至少确认能买到同型号 MCU 板）
- [ ] 拆机工具 + SWD/JTAG 编程器（读保护可能需先解锁）
- [ ] 先用 `tools/ota_watch.py` / 路由器 tcpdump 抓到官方 OTA 包（合法固件样本）
- [ ] 逆向 MCU 架构（ARM Cortex-M？）与电机驱动电路
- [ ] 只改"速度常量/摇椅功能位"级别的补丁，先离线验证 CRC/签名

**在拿到官方固件样本之前，不要向椅子发任何升级指令。**

## 5. 现实建议

| 诉求 | 可行方案 |
|---|---|
| 更快摆动 | 软件已做到：后仰 3 秒 / 回正 2 秒（约 6 秒一圈），可再调到 2/1 |
| 真·摇椅体感 | 只能换 RT7709Pro / A50Max 等带摇椅机构的机型 |
| 官方固件 | 只在 App「设备升级」里留意；**不要**用第三方工具刷 |
